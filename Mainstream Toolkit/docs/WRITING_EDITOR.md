# Visual and Markdown writing

Chapters, manuscript revisions, publication bodies, and book title/copyright pages have a **Visual / Markdown** switch and a **Markdown help** button. New browser preferences default to Visual; the last chosen mode is remembered locally. Text remains Markdown in existing database fields and exports. There is no new content migration or third-party editing service.

Visual controls: paragraph, H1/H2/H3, bold, italic, bullets, numbered lists, block quotes, undo, and redo. Keyboard shortcuts support bold, italic, undo/redo and the standard editor keys. Typing heading markers, a list marker, or `>` followed by a space converts the current block live. Switching to Markdown exposes the source generated by visual edits. Save/Preview buttons retain their original behavior: changing modes does not publish or save anything automatically.

Existing source is kept byte-for-byte until a visual document edit; conversion can normalize Markdown syntax and spacing after edits. Standard CommonMark formatting is supported. Drafts using HTML, tables, checklists, or footnotes stay in Markdown mode to avoid flattening unsupported structures. Referenced Markdown images appear as text placeholders inside the editor without loading remote artwork. The original textarea remains usable if JavaScript is unavailable. Character limits and server validation remain in force.

Public Reading Room bodies and previews now render permitted Markdown formatting. Raw HTML is displayed as literal text; the generated HTML is additionally sanitized. Chapter previews use the same renderer. Canonical stored publications and ordinal content are not rewritten by display rendering.

Frontend source is in `web_platform/frontend/writing-editor*`. ProseMirror dependencies are pinned in package-lock.json and bundled into local static JavaScript/CSS with `make build`; no CDN is required. To verify: `make test` and `make check`.

Validation: Django save/render tests cover Markdown persistence, formatting, and HTML escaping. Node tests cover heading/list/quote changes, undo, document round trips, and unsupported syntax. Browser checks cover input-rule heading conversion, bold-to-Markdown conversion, help display, and saving an analyzed revision.
